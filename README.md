# TopoPyc

JIT/AOT-компилятор для Python. Превращает функции и циклы на Python в нативный машинный код со скоростью C без переписывания на C++ или Cython.

## Зачем это нужно

В стандартном Python (CPython) каждое число — это объект `PyObject` в куче (16–24 байта), а каждая операция проверяет типы в рантайме. Из-за этого численные циклы работают в 20–200 раз медленнее, чем на C.

TopoPyc анализирует типы и зависимости данных до выполнения, доказывает мономорфизм и компилирует тело функции напрямую в машинные инструкции (AVX/FMA). Значения хранятся в регистрах процессора, без аллокаций и без накладных расходов сборщика мусора.

## Использование

### JIT-декоратор `@topojit`

Добавьте декоратор перед функцией с числовыми расчетами:

```python
from topopyc import topojit
from math import sin

@topojit
def simulate(steps: int, dt: float) -> float:
    pos = 0.0
    vel = 1.0
    for i in range(steps):
        force = -sin(pos) * 2.5
        vel += force * dt
        pos += vel * dt
    return pos

# При первом вызове функция компилируется в машинный код
print(simulate(10_000_000, 0.001))
```

### Консольный интерфейс (CLI)

```bash
# Компиляция в автономный исполняемый файл (не требует Python):
topopyc script.py -o app
./app

# Компиляция в модуль CPython (.so):
topopyc script.py --so -o module.so

# Генерация C-кода для просмотра:
topopyc script.py --emit-c
```

## Как это устроено

1. **Распаковка значений (Unboxing)**. Скалярные переменные размещаются в регистрах процессора (`%xmm`, `%rax`), а не в куче.
2. **Статический вывод типов через пучки Ходжа**. Анализирует поток данных функции и гарантирует неизменность типов на всем пути исполнения, избавляя от проверок в рантайме.
3. **Объединение операций (Kernel Fusion)**. Находит плотные группы зависимостей (кривизна Оливье–Риччи) и собирает их в единые инструкции FMA (Fused Multiply-Add).
4. **Статическое время жизни памяти**. Симплектическая модель отслеживает частоту обращений к переменным и освобождает буферы без пауз сборщика мусора.
