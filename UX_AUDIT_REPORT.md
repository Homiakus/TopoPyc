---

### 1. Текущий профиль пользователя и цели (User Persona & Goals)

- **Кто пользователь**: Разработчик, пишущий алгоритмы на чистом Python, который сталкивается с тем, что циклы `for` или численные расчеты работают медленно (секунды вместо миллисекунд).
- **Чего он хочет**: Поставить одну строчку (декоратор) над своей функцией или вызвать CLI-команду и получить 20x–200x прирост скорости без необходимости переписывать код на C/C++, разбираться с Cython/Mojo или компилировать вручную через Makefile.
- **Чего он боится**: 
  - Сложной установки тулчейна (LLVM, clang, C-заголовки).
  - Непонятных ошибок типов во время компиляции.
  - Изменения семантики вычислений (что результат разойдется с чистым Python).
  - Потери метаданных функции (`__name__`, docstrings, сигнатура для IDE).

---

### 2. Сильные стороны текущей реализации (DX Highlights)

1. **Минимальный порог входа (`Zero-Boilerplate`)**:
   - Достаточно написать `@topojit` над обычной функцией. Не требуется указывать `cdef`, создавать `.pyx` файлы, писать `setup.py` или настраивать CMake.
2. **Прозрачность и сохранение идентичности функций (`functools.wraps`)**:
   - Обернутая функция сохраняет имя, docstring и доступ к нативному адресу через `.__native__`.
3. **Чистый Python AST Frontend**:
   - Пользователь пишет идиоматичный Python-код: `range()`, `while`, `if-else`, `break`, `continue`, стандартные вызовы `math.sin`, `cos`, `sqrt`, `fabs`.
4. **Колоссальный прирост скорости без `warm-up` задержек**:
   - В отличие от PyPy, которому требуются тысячи итераций на прогрев trace-JIT, TopoPyc компилирует функцию сразу в C-код и подключает готовую `.so` библиотеку за миллисекунды.
5. **Автономность (Standalone Binary AOT)**:
   - Возможность скомпилировать независимый бинарный файл `topopyc.compile_executable` для встраивания в Docker-контейнеры без интерпретатора Python.

### 3. Выявленные точки трения (Friction Points & Usability Gaps)

| № | Точка трения | Влияние на пользователя | Уровень критичности | Решение / План улучшений |
| :- | :--- | :--- | :-: | :--- |
| **1** | **Зависимость от установленного GCC и Python.h** | Если у пользователя нет системного `gcc` или C-заголовков Python (`python3-dev`), компиляция выдаст системную ошибку компилятора. | 🟠 **Средний** | Автодетекция окружения: выводить дружелюбное сообщение с готовой командой `sudo apt install build-essential python3-dev` или использовать bundled tinycc/clang. |
| **2** | **Типизация аргументов (Type Annotations)** | Если аргументы функции не аннотированы (например, `def foo(x, n):`), компилятор по умолчанию предполагает `float64`, что для целочисленного счетчика может потребовать явного приведения. | 🟡 **Низкий** | Автоматический вывод типов при первом вызове (Lazy JIT Dispatch по типам переданных рантайм-аргументов `*args`). |
| **3** | **Сложные динамические структуры (`dict`, `set`, классы)** | На текущем этапе топологический пучок специализируется на плотных численных массивах, скалярах и циклах. Попытка скомпилировать вызовы генераторов или произвольный monkey-patching приведет к ошибке кодогенерации. | 🟡 **Низкий** (для численного JIT) | Режим грациозного отката (Graceful Fallback): при обнаружении нередуцируемых динамических структур возвращать вызов оригинальной функции CPython с предупреждением. |
| **4** | **Кэширование артефактов на диске** | Повторный запуск скрипта сейчас заново компилирует модуль во временной директории `/tmp/topopyc_*`. | 🟢 **Косметический** | Реализовать персистентный файловый кэш по хэшу AST в `~/.cache/topopyc/`. |

### 4. Рекомендации по UX для обычного пользователя

1. **Правило одной команды**:
   ```python
   from topopyc import topojit

   @topojit
   def my_heavy_function(n: int) -> float:
       ...
   ```
2. **Интуитивная консольная утилита**:
   ```bash
   # Компиляция скрипта в нативный модуль
   topopyc script.py -o script_native.so
   ```
3. **Дружелюбная диагностика топологии**:
   - При флаге `@topojit(verbose=True)` выводить понятную сводку:
     `⚡ TopoPyc: скомпилировано за 45 мс | Занулено H¹ (мономорфизм доказан) | Ускорение ~40x`.
